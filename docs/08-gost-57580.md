# Соответствие ГОСТ Р 57580.1 и hardening

Блок связывает техническую реализацию SOC с требованиями регулятора (Банк России, ГОСТ Р 57580.1-2017
«Безопасность финансовых (банковских) операций. Защита информации…»).

> Формулировки требований ГОСТ не копируем в репозиторий (документ распространяется
> по правилам Росстандарта). Ссылаемся на номера мер и приводим, чем стенд их закрывает.

## 1. Карта «мера ГОСТ → реализация в стенде»

Таблица — рабочий артефакт, сверяйте нумерацию с актуальной редакцией стандарта и
профилем защиты (уровни 1–3). Группы процессов ГОСТ Р 57580.1: РВП (регистрация/мониторинг),
УЗП (управление доступом), ЗВК (защита вычислительных сетей), АНЗ (анализ защищённости) и др.

| Группа мер ГОСТ | Смысл меры | Чем закрывает стенд | Артефакт-доказательство |
|-----------------|-----------|---------------------|-------------------------|
| РВП (регистрация событий) | сбор и хранение событий ИБ | Wazuh: централизованный сбор журналов Windows/Linux/Sysmon | скриншот Dashboard, ossec.conf |
| РВП (мониторинг и реагирование) | выявление инцидентов | правила обнаружения + корреляция, матрица ATT&CK | rules/, docs/03-coverage.md |
| РВП (защита журналов от изменения) | целостность журналов | детект очистки журналов (rule 100150), пересылка на отдельный хост | rule 100150, отчёт по инциденту |
| УЗП (управление учётными записями) | контроль создания/прав УЗ | детект создания УЗ и выдачи админправ (100140/100141) + активное реагирование | rules, active-response/ |
| ЗВК (защита сетей) | сегментация, контроль трафика | изоляция стенда (host-only), Suricata NIDS | docs/01, docs/04 |
| АНЗ (анализ защищённости) | контроль конфигураций | Wazuh SCA: оценка по CIS Benchmark | sca/, отчёт SCA «до/после» |
| РИ (реагирование на инциденты) | процессы реагирования | плейбуки, кейсы в TheHive, отчёты | reports/, docs/07 |

Полная версия с конкретными номерами мер — в [sca/gost-mapping.csv](../sca/gost-mapping.csv)
(заполняется по мере прохождения; оставлены примеры строк).

## 2. Контроль конфигураций через Wazuh SCA

Wazuh Security Configuration Assessment периодически проверяет хост по политике и даёт
процент соответствия. Используем встроенные политики CIS для Windows 10 и Ubuntu:

- в `ossec.conf` агента блок `<sca>` включён по умолчанию;
- результат: Dashboard → Modules → Security Configuration Assessment → score, список
  проваленных проверок.

Сценарий для отчёта (и прямая иллюстрация меры АНЗ):
1. Снять SCA-скор на «ванильной» Windows 10 → зафиксировать (например, 40–50%).
2. Применить hardening: отключить SMBv1, включить аудит и логирование PowerShell
   (это делает `install-agent.ps1`), настроить политику паролей/блокировки, UAC.
3. Повторить SCA → показать рост скора и закрытые проверки.
4. График «до/после» + таблица закрытых пунктов → в документацию и README.

## 3. Мини-политика SCA под стенд

Небольшая собственная политика [sca/soc-lab-sca.yml](../sca/soc-lab-sca.yml) проверяет
именно те настройки, от которых зависит наша телеметрия (аудит создания процессов,
ScriptBlockLogging, Sysmon-служба).
